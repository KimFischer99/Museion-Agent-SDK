## 1. 版本目标与完成定义

用户通过一个可信信息入口表达要求。PAS 将明确要求转成可执行的提醒、定期研究或持续关注，结合已授权的会话、笔记、记忆和公开来源进行研判，并通过既有投递链路交付。没有邮件、日历、支付账号接入时，这条链路也必须成立。

本版本交付三条完整路径：

1. 用户请求 → 明确内容和时间 → 持久化 reminder → 到期发送冻结文案。
2. 用户要求定期研究 → 按期抓取可用公开来源 → 结合历史材料分析 → 按约交付结果。
3. 用户授权持续关注 → 周期读取相关内部上下文和公开来源 → 有依据且有价值时主动联系，否则保留静默原因。

任务建立、分析成功、消息排队、实际投递是不同状态。只有任务真实持久化后才能回复“已安排”；只有投递状态提供证据时才能称为“已投递”。

## 3. 行为契约

执行承诺和发送条件分别表达，不能仅凭“有无来源变化”决定是否履行任务。

| 意图 | 映射原则 | 结果要求 |
|---|---|---|
| 到时提醒 | reminder + due + 现有 schedule | 固定文案；零 run/模型调用；沿用投递门和漏执行规则 |
| 定期研究并交报告 | task + always_run + due；显式研究范围和选源 | 到期执行；无新条目仍能报告本轮查证结果；失败可查询且不得冒充无变化 |
| 有重要进展再通知 | 来源型 heartbeat，或需要内部上下文的 task + always_run + opportunistic | 研究/检查不等于必须发送；仅有依据且值得打扰才通知 |
| 依据会话、笔记、记忆跟进 | 已授权的周期 task + always_run + opportunistic | 定期重新评估事项和期限；不依赖外部候选出现 |
| 仅保存偏好或事项 | 既有兴趣/记忆入口 | 返回“已记录”，不冒充已建立后台任务 |

`always_run` 只表达运行依据，不授予额外权限，也不保证投递。实施时核对 quiet/idle/cadence 门与 `obligation` 的关系：due 研究不得因用户正在聊天被悄悄取消；静默窗口内可延后交付，但必须留下可恢复的待办状态。不能只修改提示词就声称完成这一语义。

v0.1.6 以已有周期调度提供上下文研判机会，不新增通用事件总线，也不要求每次笔记写入都立即唤醒。既有纯来源 heartbeat 保留无变化零模型调用行为。

## 4. 实施顺序

### P1：统一可信输入与任务落库

责任文件：`proactive.py`、`facade.py`、`service.py`、`rpc_server.py`，及直接相关契约/宿主入口。

- 扩展现有输入解析，返回受校验的意图与参数：任务内容、时间/时区、研究范围、来源选择、交付要求。参数尽量直接采用现有 JobSpec 字段。
- 模型负责理解和提出候选；可信控制层关联原始用户请求、校验权限并调用现有写入口。后台分析输出、网页、笔记和历史引用不能作为新的授权。
- 明确请求且授权充分时直接建立；缺少影响执行的关键参数才澄清。没有可用来源、时间无法表示或权限不足时，返回具体缺口，不降级成一条 watch 后声称安排成功。
- 回复包含创建/记录/需澄清/失败的真实结果，创建成功附 job ID、可读规则和 next_due。重复投递同一用户请求保持幂等；修改既有任务使用其 revision 规则。
- Hermes 复用相同可信入口，身份和用户请求关联由宿主提供，不能依靠模型自报 actor。不要简单放开后台模型可调用工具的 reminder 权限。
- 既有 schedule 覆盖范围先交付；复杂多时刻/窗口表达明确报告限制，不为了 issue 示例先设计新的调度语言。

完成标准：同一入口可以建立 reminder、定期研究和机会型关注，且能区分“记录信息”与“建立任务”。

### P2：接通内部上下文与来源装配

责任文件：`examples/release_app.py`、`examples/deployment/`、`context.py`、`coordinator.py`、现有端口与配置透传。

- 采用已有 `ConversationPort` 和 `MemoryPort` 注入当前 profile 获准读取的数据。笔记通过明确配置的只读来源/宿主端口提供，保留来源标识、修改时间和证据引用；不默认扫描用户目录。
- 提供一个可运行的本地装配例子：有限会话、SQLite 记忆、指定笔记文件和公开来源共同进入 ContextPack。文件笔记适配只实现本版本需要的有界读取，不建设通用连接器平台。
- 宿主文件记忆与 SQLite 学习记忆必须明确合并，不能替换端口后丢掉已有学习记忆。继续保持 TTL、forget 和范围过滤。
- 上下文研判任务明确使用周期 task 路径；不用外部 source 是否变化作为唯一运行门。会话未接入、端口失败、没有相关材料分别返回真实状态。
- 不每轮注入全部资料；复用现有读取预算、记忆排序和上下文裁剪。目标、会话、反馈开关按装配显式启用。

完成标准：外部来源未变化时，已授权会话或笔记中的临近事项仍能在下一研判周期被考虑；材料为空时不虚构理由联系用户。

### P3：定时研究与按约交付

责任文件：`research.py`、`context.py`、`coordinator.py`、policy/store/dispatcher 的受影响调用路径，以及选源字段透传。

- 将当前固定“公开新闻兴趣”的装配扩展为按任务绑定研究问题和已注册来源。复用 RSS 搜索与公共来源；查询范围来自用户任务或既有授权主题。
- 明确研究任务每个到期 occurrence 都执行所需抓取和分析。来源差异为空时，可以使用本轮成功读取的数据及有日期的历史快照；不能把只含 delta 的空数组解释为“没有任何研究材料”。
- 区分“获取本轮材料”和“筛选变化候选”：必要时在现有来源/快照链路补最小接口，保留快照来源及新鲜度。旧快照不得仅因本次抓取失败而被标成已刷新。
- 第一版研究范围为已授权公开来源材料的比较、归纳和关联分析。只读到标题/摘要时明确标注；不承诺任意网页全文、无限搜索或未配置的外部服务。
- 按约报告与机会型通知分别执行交付要求。成功但无新进展可形成有依据的检查报告；全源失败保留失败状态，按约任务还应提供明确失败反馈，不能伪装成研究结论。复用现有通知路径，若需要非模型状态反馈，必须有可审计的系统来源。
- 已完成分析但被 quiet 等投递门延后的结果进入已有待投递路径；不得丢弃后要求重新生成同一报告。外部投递 unknown 继续禁止盲目重发。

完成标准：无需私人账号连接器，一项周期研究能跨重启执行、给出来源明确的结果，并在投递记录中追踪到最终状态。

### P4：版本与发布收口

- 公共字段如有变化，同步 Python、JSON Schema、生成 TypeScript、CLI/RPC 和受影响 fixture；优先使用已有字段，不预设新的数据库表。
- 若确需持久化新增状态，使用追加迁移；不改历史迁移。升级和回滚要求写进交付记录。
- 完成实现后统一将 `pyproject.toml`、`src/proactive_sdk/__init__.py`、`packages/client-ts/package.json`、README 当前版本改为 `0.1.6`；历史验收记录不批量替换。
- 文档提供从用户输入到查询任务、查看研究结果和投递状态的完整示例；更新兼容性说明，明确模拟检查、真实模型及真实外部投递各自证据。
- 提交、推送、发布、生产部署需相应授权；本方案不替代这些授权。

## 5. 验证预算与验收

本轮已完成的基线证据：scheduler、reminder、Hermes plugin 相关现有测试合计 **55 项通过**。这是 v0.1.5 路径的结果，不代表 v0.1.6 已实现或验证。

实现任务新增行为用例总计最多 5 个，每个参数化输入单独计数，不按阶段重置：

| 用例 | 可观察结果 |
|---|---|
| 1. 明确提醒请求 | 通过统一入口落库，重开 store 后到期投递冻结文案，无 run、无模型发送调用 |
| 2. 已授权周期研究 | 来源成功读取但内容未变化时仍履行一次研究；结果有真实来源，交付记录可查询 |
| 3. 内部上下文跟进 | 外部源未变化，指定笔记中的到期事项仍进入研判；重复周期不重复投递同一事实 |
| 4. 来源抓取失败 | 研究标记失败，不推进成功查证状态，不将旧快照冒充新信息；失败反馈可追踪 |
| 5. 不可信创建指令 | 笔记/外部材料要求创建 reminder 时不会形成新任务或授权 |

复用现有测试验证单次/周期 slot、DST、静默/idle/cadence、授权撤销、schema/type 漂移和投递恢复。无法用既有证据覆盖的关键行为如影响完成定义，应报告具体缺口，申请一次有界验证扩展，不追加无上限测试矩阵。

每次实现完成后运行最小相关检查集合一次；仅相关修正允许一次针对性复跑。提交前必须执行 `docs/CONTRIBUTING.md` 明列的全量/示例/许可/类型/构建/制品/安装检查，不重复运行已通过且未受后续修改影响的门。环境缺失、超时、跳过分别记录；需要安装依赖时先按授权边界处理。

使用公开来源和本地 inbox 完成不含私人账号的真实运行验收；调用付费模型和外部投递须有授权。缺少这类运行证据时，报告实现完成与实际链路未验收，不把 stub 结果称为真实主动性验证。

## 6. 明确不并入本版本的事项

- 邮件、日历、支付等新增账号集成；跨用户/跨设备平台；新的通用信息总线。
- 用 `times` 扩展替代统一意图与研究链路；复杂任意时间语言的全面支持。
- nanoMuse 的模型生成 reminder 文案方式；PAS 保留确定性提醒。
- 来源全部失败静默降级为“无变化”。
- issue 中 Unix socket、重连 hello、扁平 instruction 已在基线修复，复用现有回归，不重复实现。
- 决策解析错误被预算错误遮蔽属于独立修复项，本版本不将其混入统合范围；若它实际阻塞上述验收，应重新明确修复范围与剩余验证预算。

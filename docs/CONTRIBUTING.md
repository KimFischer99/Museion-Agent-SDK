# Contributing (CONTRIBUTING)

## Required reading first

`docs/SECURITY.md` (authorization boundaries), `schemas/README.md` (public contracts),
`docs/COMPATIBILITY.md` (measured support scope). **Do not** describe a skip, mock, TODO or
interface stub as a completed capability.

## Working conventions

- Continue with the gaps listed in the compatibility matrix; distinguish scripted contract tests
  from real-service integration.
- Keep every PR runnable and testable; a public schema change must land in Python, TypeScript
  (`packages/client-ts`, generated by `tools/gen_client_ts.py`) and the fixtures together.
- store migrations are additive only; a new failure mode gets a new recovery test.
- Do not start background threads/processes at import time; do not implement implicit inheritance
  of host credentials.
- Performance figures must state their environment; if it has not been measured, do not write
  "achieved".

## Local verification (all of it must pass before committing)

```bash
python -m unittest discover -s tests            # full unit/contract suite
python examples/reference_core.py               # reference demo output must not change
python examples/agent_loop_demo.py
python examples/policy_delivery_demo.py
python examples/skills_loop_demo.py
python tools/license_gate.py                    # license gate
python tools/gen_client_ts.py                   # client-ts idempotency
npm exec --yes --package=typescript@5.8.3 -- tsc -p packages/client-ts/tsconfig.json
python -m pip wheel . -w dist --no-deps         # build the artifact
python tools/package_gate.py dist/*.whl         # artifact scan (not a git scan)
python tools/gen_sbom.py dist/*.whl -o dist/sbom.cdx.json
python tools/install_smoke.py dist              # fresh-venv install smoke
```

`tests/fixtures/skills.json` holds the compatibility regression baseline for the 88 entry points;
`tests/fixtures/selected-source-manifest.json` guards against private original files leaking into
artifacts. Both are development and build data and do not take part in the SDK runtime. If a
machine keeps the complete private source attachment, `python tools/reproduce_audit.py` can
reproduce the original audit separately; it is not a deployment prerequisite.

## Commit messages

A one-line subject (phase/ticket + summary), with the body listing: contract changes,
compatibility impact, test evidence, known gaps. Never treat a long-standing TODO as done.

## Distribution red lines

- `01/` (including the Muse original files under `private-vendor/`, private helper copies,
  credentials, environment files and `muse-refer/`) stays local only: not into git, not into the
  package, not into containers, and never uploaded to a public channel.
- `_deployment_reference/skills/` is an explicitly bundled deployment reference; keep its
  provenance inventory and file hashes in step, and never wire it into the default runtime or
  execute it automatically.
- Do not use the license of a same-named Muse SDK from elsewhere to override this project's
  constraints.
- Provenance/license/privacy scanning for containers and generated packages targets the artifact
  itself (package_gate), not just git-tracked files.
